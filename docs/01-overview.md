# 第 1 章　USB 全景：先建立一张地图

## 本章目标

- 用一句话说清 USB 的核心规则：**主机说了算，设备只回答**
- 认识分层星形拓扑、设备地址、端点、管道这几个贯穿全书的词
- 知道 USB 的几种速度，以及本教程聚焦的“全速 12 Mbit/s”
- 搭好环境：编译本教程的模拟器和全部例子，跑通自测

## 1.1 为什么要学协议，而不是只会调库

很多人做 USB 的经历是：从网上抄一份 CubeMX 工程，插上电脑能识别就收工；一旦出了“无法识别的 USB 设备”“传到一半卡住”“Linux 下能用 Windows 下不行”，就只能到处搜。

问题在于 USB 的错误几乎都发生在**看不见的地方**：线上的包、主机驱动里的重试、描述符里的一个字节。本教程的思路是：

1. 先在 PC 上用一个**纯软件的 USB 模拟器**（`miniusb`，全部是 C++ 头文件）把协议从电平到枚举一层层搭出来。每一步都能打印出线上到底发生了什么，不需要任何硬件，也不需要几千块的协议分析仪。
2. 再用 **libusb** 在 PC 上写真正的主机程序。
3. 最后用 **STM32 + TinyUSB** 做一个真正的 USB 设备，并用前面写的主机程序和它对话。

学完后你再看 TinyUSB 或 ST 的 USB 库，会发现它们做的事你都在模拟器里亲手做过一遍。

## 1.2 一张图看懂 USB

![USB 全景](images/01-topology.svg)

**左边是物理连接**。USB 是一棵树：根是电脑里的**主机控制器**和**根 Hub**，Hub 可以继续接 Hub，叶子是各种设备。规则很简单：

- 一条总线上**只有一个主机**。两个设备之间不能直接通信，U 盘不能直接把文件拷给另一个 U 盘。
- 每个设备在枚举时被分配一个 **7 位地址**（1–127，0 留给“刚插上还没分配地址的设备”）。
- 线缆只有 4 根：VBUS（5 V 供电）、GND、**D+、D−**。数据就在 D+/D− 这对差分线上，半双工，同一时刻只有一方在说话。

**右边是逻辑分层**，这是理解 USB 最重要的一张图。每一层都只和对面的同一层“对话”：

| 主机侧 | 设备侧 | 它们在聊什么 | 本教程章节 |
|--------|--------|--------------|-----------|
| 应用程序、类驱动 | 功能（接口 + 端点） | “给我一个按键报告”“写 512 字节到串口” | 第 8、9、10 章 |
| USB 核心驱动 | USB 设备层（端点 0） | “你是谁？”“你的地址是 5”“启用配置 1” | 第 6、7 章 |
| 主机控制器（xHCI 等） | USB 控制器 + PHY | 包、事务、重试、每毫秒一帧 | 第 2–5 章 |

## 1.3 主机说了算

USB 最反直觉的一点：**设备从来不主动发送任何东西**。

你按下键盘的一个键，键盘并不能“立刻告诉”电脑。真实情况是：主机每隔几毫秒问一次键盘“有新数据吗？”，键盘这次才把按键报告交出去；没有按键时它回答 **NAK**（“现在没有”）。

“设备发数据给主机”在 USB 里叫 **IN**，“主机发数据给设备”叫 **OUT**。方向永远是**站在主机的角度**命名的。这个约定贯穿全书，记住它能少踩很多坑。

## 1.4 端点和管道

一个设备上可以有多个数据收发口，叫**端点**（endpoint），编号 0–15，每个编号还分 IN 和 OUT 两个方向。写法上用一个字节表示，最高位是方向：

| 端点地址 | 含义 |
|---------|------|
| `0x00` / `0x80` | 端点 0，每个设备都必须有，专门做“控制” |
| `0x01` | 1 号 OUT 端点（主机 → 设备） |
| `0x81` | 1 号 IN 端点（设备 → 主机） |
| `0x82` | 2 号 IN 端点 |

主机软件和设备某个端点之间的逻辑通道叫**管道**（pipe）。端点 0 上的那条叫**默认控制管道**，设备一插上就存在，主机靠它完成“认识设备”（枚举）的全过程。其他端点要等枚举完成、设备被“配置”之后才可以用。

## 1.5 速度

| 名称 | 速率 | 典型设备 | 规范 |
|------|------|---------|------|
| 低速 Low Speed | 1.5 Mbit/s | 老式键盘鼠标 | USB 1.0 |
| 全速 Full Speed | 12 Mbit/s | 大部分单片机、串口、键盘、声卡 | USB 1.1 |
| 高速 High Speed | 480 Mbit/s | U 盘、摄像头 | USB 2.0 |
| 超速 SuperSpeed | 5 Gbit/s 及以上 | 移动硬盘 | USB 3.x |

> “USB 2.0 接口”不等于“480 Mbit/s”。USB 2.0 规范同时包含低速、全速、高速三种，STM32F103/F407 自带的 USB 都是 **USB 2.0 全速**设备。

本教程聚焦**全速**：单片机最常见，协议也最完整（高速只是在全速基础上加了 PING、NYET、微帧等优化，第 3、5 章会顺带提到）。USB 3.x 的物理层完全不同，不在本书范围。

## 1.6 搭建环境

需要的东西：

- 一台 Linux 机器，或 Windows 上的 **WSL2**（本教程就是在 WSL2 Ubuntu 上写的）
- `g++`（支持 C++17）、`cmake`（3.16 以上）
- 第 10 章需要 `libusb-1.0-0-dev`；第 11 章需要 `arm-none-eabi-gcc` 和隔壁 `../stm32` 教程的工程框架，到时候再装

```bash
sudo apt install g++ cmake make
cd usb                       # 本教程根目录
cmake -S . -B build          # 生成构建文件
cmake --build build -j       # 编译模拟器的全部例子
./build/tests/test_miniusb   # 自测：用规范里的已知数据校验模拟器
```

本机实际输出（还没装 libusb 时，CMake 会提示跳过第 10 章，不影响其他章节）：

```
-- 没找到 libusb-1.0，跳过第 10 章的例子。安装：sudo apt install libusb-1.0-0-dev
-- Configuring done (1.1s)
-- Generating done (0.0s)
-- Build files have been written to: build
...
全部通过
```

`test_miniusb` 用几组“标准答案”检查模拟器，比如 SETUP 令牌包（地址 0、端点 0）必须编码成 `2D 00 10`、字符串 `"123456789"` 的 CRC16 必须是 `0xB4C8`。这些数字在后面几章都会亲手算一遍。

编译出来的例子都在 `build/examples/` 下，名字和章节号对应：

```
build/examples/02-signal          第 2 章 物理层
build/examples/03-packet          第 3 章 包
build/examples/04-transaction     第 4 章 事务
...
build/examples/09-cdc-serial      第 9 章 CDC 串口
build/examples/12-troubleshoot    第 12 章 排错
```

第 10 章的 `lsusb_lite`、`vendor_client` 装了 libusb 才会编译出来；第 11 章是 STM32 固件，在它自己的目录里用 `make` 编译。

## 1.7 模拟器长什么样

`include/miniusb/` 下每个头文件对应协议的一层，后面的章节会逐个打开它们：

| 头文件 | 对应协议层 | 章节 |
|-------|-----------|-----|
| `signal.hpp` | NRZI 编码、位填充、J/K/SE0 电平 | 第 2 章 |
| `crc.hpp`、`packet.hpp` | PID、CRC5/CRC16、四类包 | 第 3 章 |
| `bus.hpp`、`trace.hpp` | 总线：把包广播给所有设备，可以注入干扰 | 第 4 章 |
| `host.hpp` | 主机：事务、重试、四种传输、枚举 | 第 4、5、7 章 |
| `descriptors.hpp`、`setup.hpp` | 描述符、SETUP 包、标准请求 | 第 6、7 章 |
| `device.hpp` | 设备：端点 0 状态机、数据翻转、类请求钩子 | 第 7–9 章 |

模拟器每一步都会打印日志，日志的详细程度可以调（`trace.level`）：

| 级别 | 显示什么 |
|-----|---------|
| `kTransfer` | 传输：“控制读 18 字节” |
| `kTransaction` | 事务：“IN → DATA1 → ACK” |
| `kPacket` | 每个包的字段 |
| `kWire` | 每个包的原始字节 |

这相当于一台免费的协议分析仪。

## 1.8 怎么学

每章的结构都一样：**原理图 → 代码讲解 → 动手运行 → 练习 → 常见坑**。建议：

1. 先看图，再跑例子，对照输出读代码。
2. 每章的练习至少做一道。练习通常是“改一个地方，预测输出，再运行验证”，这是最快的学习方式。
3. 遇到看不懂的输出，把日志级别调高一级再跑一次。

## 练习

1. 用自己的话回答：USB 键盘是怎么在你按键后 10 ms 内让电脑知道的？设备主动发了什么吗？
2. 端点地址 `0x83` 和 `0x03` 分别是什么？哪一个是“设备发给主机”？
3. 看看自己电脑上的 USB 设备：Windows 打开“设备管理器 → 通用串行总线控制器”，或者在原生 Linux 上运行 `lsusb -t`，画出你电脑上的 USB 树。（WSL2 默认看不到 USB 设备，第 10 章会讲怎么把设备转发进去。）

## 常见坑

- **把 IN/OUT 当成站在设备角度。** 永远站在主机角度：IN = 进主机。
- **以为 USB 2.0 就是高速。** 先看芯片手册写的是 Full Speed 还是 High Speed。
- **以为设备可以主动上报。** 即使是“中断传输”，也是主机定时轮询，第 5 章会算这个间隔。
